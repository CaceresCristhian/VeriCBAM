### 1.2 Other clutter and gaps

1. **Generated caches.** `__pycache__/` folders exist under `src/` (e.g., `src/core/bayesian/__pycache__/*.pyc`). These should never be shipped.
2. **No `.gitignore`.** Nothing prevents caches, virtual environments or large raw data from being committed or zipped.
3. **`data/01_raw/` is 665 MB.** About 663 MB of it is `eprtr_reference/csv_tables/` (16 EEA CSVs). No script in `src/`, `scripts/`, `experiments/` or `tests/` reads from `01_raw` (verified by searching the code), so the raw tables are provenance material only.
4. **The cohort has no generating script.** `data/02_processed/benchmark_cohort.parquet` is read by the pipeline but nothing in the repo builds it from the raw EEA tables. `reproduce_all.py` starts at the technology registry. The "reproducible" claim has a gap here (see Step 7).
5. **A script lives in the wrong place.** `src/generate_official_application_pdf.py` is an administrative form-filler, not part of the model code. It reads `Capstone_Application_Form.pdf` and writes `..._Filled_v2.pdf` from the current working directory, so it breaks when those PDFs move.
6. **Duplicated outputs.** `experiments/results/` holds each result in several formats (`.csv`, `.parquet`, `.json`) plus a 4.7 MB Plotly HTML (`calibration_and_roc_curves.html`). These are generated by `reproduce_all.py` and are fine to keep, but they go stale when the README is edited by hand (see the separate review: README metrics don't match the saved results).
7. **Stale or broken references** to files that will move (listed in Step 6):
   - `src/ui/app.py` line ~732 names `VeriCBAM_Capstone_Application_Form_Filled_v2.pdf`.
   - `Capstone_Proposal_Document.md` line 10 names the non-v2 filled form, which Step 2 deletes.
   - `README.md` repository tree lists the PDF and plan at the root.
   - `README.md` install section hard-codes `C:\Users\crist\Projects\UEprojects\Capstone`.
8. **Personal data.** The README header contains the matriculation number. Fine for a university submission, but remove it before publishing on GitHub.
9. **No `__init__.py` files** in `src/` or `tests/`. The code works through `sys.path.insert(...)` hacks in several scripts. This is not clutter, but worth fixing while tidying (Step 8).

## 2. Step-by-step cleanup

### Step 0: Back up everything

```powershell
cd C:\Users\crist\Projects\UEprojects
Compress-Archive -Path .\Capstone -DestinationPath .\Capstone_BACKUP_before_cleanup.zip
```

If the project is under git, also run `git status` and commit or stash any pending work, then create a branch: `git checkout -b cleanup`.

### Step 1: Record a baseline (so you can prove nothing broke)

```powershell

python -m pytest -q 2>&1 | Tee-Object ..\baseline_pytest.txt
```

### Step 5: Decide what to do with the 665 MB of raw EEA data

Pick **one** option.

- **Option A (recommended for the submission zip):** keep `data/01_raw/` locally and exclude it from the zip. Document how to download it (EEA Industrial Reporting Database v16, the URL is in `docs/DATA_PROVENANCE.md`). Add `data/01_raw/eprtr_reference/csv_tables/` to `.gitignore` (Step 8) and to the exclude list in `scripts/build_reproducible_zip.py`.
- **Option B:** keep everything and accept a ~665 MB zip. Only do this if the university requires the raw data.
- **Option C:** trim `csv_tables/` to the only tables the cohort build actually needs (the facility-level air release file, `F1_4_Air_Releases_Facilities.csv`, is the likely one) and delete the other 15. Only do this after you have a script that builds the cohort (Step 7), so you know which tables are used.

Keep `data/01_raw/eprtr_reference/eea_t_ied-eprtr_p_2007-2024_v16_r00/` (1.4 MB): it holds the EEA README and the metadata PDF that document the data.

### Step 7: Close the reproducibility gap (cohort build)

The pipeline cannot rebuild `benchmark_cohort.parquet`. Either:

- **(a)** Write `src/data_loaders/build_cohort.py` that reads the EEA CSVs from `data/01_raw/`, selects the 30 facilities and 2018-2023 years, and writes `data/02_processed/benchmark_cohort.parquet`. Add it as stage 0 of `scripts/reproduce_all.py`; or
- **(b)** State in `docs/DATA_PROVENANCE.md` that the cohort parquet is a frozen input, record which EEA table and filters produced it, and include its SHA-256 hash.

Option (a) is stronger and also tells you which raw tables you actually need for Step 5, Option C.
